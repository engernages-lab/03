同样地，success 代表以下断言全部成立（该步骤内任一失败即 `exit 1`）：

| 断言 | 实现方式 | 结果 |
| --- | --- | --- |
| 读取容器真实上限 | `docker exec <container> printenv POCKETSCORE_MAX_UPLOAD_MB` | ✅ 成功读取（未假设 50） |
| 生成真实超限文件 | `printf 'RIFF'` + `head -c $((size*1024*1024)) /dev/zero`，`size = limit + limit/10 + 1` | ✅ 真实字节 |
| 超限请求 | 带令牌 `POST /api/v1/audio/upload` | ✅ 返回 **413** |
| 错误信封 | 响应体含 `PAYLOAD_TOO_LARGE` | ✅ |
| 限额内 WAV | `tests/fixtures/melody.wav` | ✅ **201** |
| 临时文件清理 | `mktemp -d` + `trap ... EXIT` | ✅ |
| 未把 415 当 413 | 该步骤断言 `= 413`；415 由步骤 23 单独断言 | ✅ 两条独立 |

**为什么不是"curl 断连假阳性"**：该步骤显式用 `code=$(curl … ) || echo "curl exit=$?"` 捕获退出码，
随后以 `test "$code" = "413"` 作为唯一判据；若服务端因 `Content-Length > limit*1.05` 提前拒绝并断连，
状态码仍为 413，断言成立；若只是断连而没有 413，`code` 会是 000 或空，断言失败。
